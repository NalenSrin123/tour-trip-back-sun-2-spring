# Payment Module — Entity Relationship Diagram

Covers the tables created in `src/main/resources/db/migration/V1__create_bookings_table.sql`.

```mermaid
erDiagram
    BOOKINGS ||--o{ PARTICIPANTS : "has"
    BOOKINGS ||--o{ INVOICES : "billed by"
    INVOICES ||--o{ PAYMENTS : "settled by"
    RECEIPTS ||--o| PAYMENTS : "issued for"

    BOOKINGS {
        bigint id PK
        bigint user_id
        bigint tour_schedule_id
        decimal total_price
        text special_requests
        varchar booking_status "Pending | Confirmed | Cancelled"
        varchar booking_type "Individual | Family | Team"
        int member_count
        boolean is_deleted
    }

    PARTICIPANTS {
        bigint id PK
        bigint booking_id FK
        varchar age_group
        varchar name
        varchar sex "Male | Female | Other"
        boolean is_deleted
    }

    INVOICES {
        bigint id PK
        bigint booking_id FK
        varchar invoice_no UK
        decimal sub_total
        decimal tax_amount
        decimal total_amount
        datetime issued_at
        boolean is_deleted
    }

    PAYMENTS {
        bigint id PK
        bigint invoice_id FK
        bigint receipt_id FK
        decimal amount
        varchar payment_method "card | bank_transfer | aba_pay"
        varchar payment_status "pending | paid | failed | refunded"
        varchar transaction_id
        datetime payment_date
        boolean is_deleted
    }

    RECEIPTS {
        bigint id PK
        varchar receipt_no UK
        datetime issued_at
        varchar tour_tittle
        datetime tour_date
        int num_travelers
        decimal sub_total
        decimal tax_amount
        decimal total_paid
        varchar payment_method
        varchar pdf_url
        boolean is_deleted
    }
```

## Notes

- All five tables use a soft-delete flag (`is_deleted`); entities apply `@SQLDelete` + `@SQLRestriction` so a `DELETE` request never removes a row, it flips the flag and existing queries transparently filter it out.
- `payments.transaction_id` is generated by the gateway layer (`payment/gateway`) at payment creation time — see [`docs/api/payment-api.md`](../api/payment-api.md).
- A `payment` optionally links to one `receipt` (`receipt_id` nullable); a `receipt` cannot be shared across payments (`@OneToOne`).
